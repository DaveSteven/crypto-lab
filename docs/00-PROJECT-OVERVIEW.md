## 1. 项目背景

虚拟货币市场具有全球化、全天候交易、公开行情数据丰富等特点，为金融知识学习、市场研究、量化交易及套利策略验证提供了实验环境。

本项目旨在构建一个基于真实市场数据、使用虚拟资金进行交易的独立研究平台。

通过数据采集、模拟交易、历史行情回放、策略回测和风险分析，逐步建立对虚拟货币市场及金融交易机制的理解。

项目不以短期投资盈利为首要目标，而以学习、研究和数据验证为核心。

## 2. 项目目标

### 2.1 学习目标

- 理解虚拟货币市场的运行机制。
- 理解现货交易及订单撮合机制。
- 掌握行情数据的阅读与分析方法。
- 理解流动性、滑点、交易成本及市场效率。
- 掌握跨交易所套利的基本原理。
- 学习量化交易及风险管理。
- 建立基于数据进行决策的能力。

### 2.2 技术目标

- 建立多交易所行情采集系统。
- 建立统一的市场数据模型。
- 实现实时行情及历史行情管理。
- 实现独立的虚拟账户管理系统。
- 实现基于真实行情的模拟交易引擎。
- 实现跨交易所价差监控与套利模拟。
- 实现历史行情回放与策略回测。
- 建立可复现的量化实验环境。

### 2.3 研究目标

通过实际数据回答以下问题：

- 不同交易所是否存在可执行的价格差异？
- 价差出现的频率及持续时间是多少？
- 扣除各类交易成本后是否存在利润空间？
- 不同市场环境下，交易策略的表现有何差异？
- 普通投资者是否具备执行相关策略的条件？
- 模拟交易结果与真实交易环境之间存在哪些差异？

## 3. 项目设计原则

### 3.1 Data First — 数据优先

数据的准确性、完整性、时效性优先于界面设计及功能数量。

未经验证的数据不得作为交易策略的决策依据。

### 3.2 Simulation First — 模拟优先

所有交易使用虚拟资金。

系统不得执行真实订单，不得连接真实钱包，不得要求用户充值。

### 3.3 Reality First — 真实市场约束

模拟交易应尽可能还原真实市场环境，包括：

- 买卖报价差异。
- 交易手续费。
- 订单簿深度。
- 成交滑点。
- 网络延迟。
- 部分成交。
- 订单失败。
- 资金占用。
- 跨交易所资金转移成本。

不得通过理想化成交逻辑夸大策略收益。

### 3.4 Evidence Based — 数据驱动

所有交易策略及研究结论必须具有可追溯的数据依据。

不得将未经验证的假设作为系统事实。

### 3.5 Reproducibility — 实验可复现

研究实验应记录：

- 数据来源。
- 实验时间范围。
- 策略版本。
- 策略参数。
- 初始资金。
- 手续费模型。
- 成交模型。
- 实验结果。

相同数据、参数及随机种子应尽可能产生一致的实验结果。

### 3.6 Modular Design — 模块化设计

行情采集、数据存储、模拟交易、策略计算及前端展示应保持相对独立。

避免模块之间产生不必要的耦合。

### 3.7 Low Cost — 低成本

优先使用公开免费 API、开源技术及本地开发环境。

未经项目负责人确认，不得引入付费服务。

### 3.8 No Look-ahead — 禁止未来数据泄漏

在历史回放及策略回测过程中，系统只能使用当前模拟时间点已经存在的数据。

禁止使用未来价格、未来成交量或其他未来信息进行决策。

## 4. 项目功能范围

### 4.1 Market Data — 市场行情

负责从交易所获取及处理真实市场数据。

主要功能：

- 实时行情。
- 历史 K 线。
- 实时成交记录。
- 实时订单簿。
- 市场深度。
- 交易对信息。
- 交易所状态。
- 行情数据质量检测。

### 4.2 Paper Trading — 模拟交易

基于真实市场行情执行虚拟资金交易。

主要功能：

- 创建模拟账户。
- 设置初始资金。
- 虚拟资产余额管理。
- 市价单。
- 限价单。
- 订单取消。
- 模拟订单成交。
- 手续费计算。
- 持仓管理。
- 已实现盈亏。
- 未实现盈亏。
- 交易记录。

初期仅支持现货交易。

禁止负余额、无资产卖出及未经定义的资金透支。

### 4.3 Arbitrage Lab — 套利实验

研究不同交易所之间的价格差异。

主要功能：

- 多交易所行情对比。
- 毛价差计算。
- 净价差估算。
- 手续费计算。
- 可成交数量估算。
- 价差持续时间统计。
- 独立交易所虚拟账户。
- 跨交易所套利模拟。
- 资产再平衡模拟。

套利机会必须根据可执行买卖报价计算，不得仅比较最新成交价。

不同计价货币、不同市场类型的交易对不得直接比较。

### 4.4 Market Replay — 历史行情回放

通过历史市场数据重现过去的交易环境。

主要功能：

- 选择交易对。
- 选择历史时间范围。
- 回放开始及暂停。
- 回放速度控制。
- 逐步推进。
- 历史模拟交易。
- 隐藏未来行情。
- 实验结果保存。

历史数据精度必须与模拟成交模型相匹配。

只有 K 线数据时，不得声称能够精确还原订单簿及实际成交过程。

### 4.5 Strategy Lab — 策略实验

建立统一的量化策略实验环境。

候选研究策略：

- Buy and Hold。
- Moving Average。
- RSI。
- Momentum。
- Mean Reversion。
- Cross-exchange Arbitrage。

以上策略仅作为研究对象，不代表推荐使用或具有盈利能力。

主要功能：

- 策略注册。
- 策略参数配置。
- 策略版本管理。
- 实时模拟运行。
- 历史回测。
- 多策略对比。
- 实验结果记录。

### 4.6 Analytics — 数据分析

主要分析指标：

- 账户总资产。
- 累计收益率。
- 已实现盈亏。
- 未实现盈亏。
- 交易次数。
- 胜率。
- 盈亏比。
- Profit Factor。
- 最大回撤。
- Sharpe Ratio。
- 手续费支出。
- 资金利用率。

指标计算方式必须具有明确的定义。

样本数量不足时，应明确提示统计结果的局限性。

### 4.7 Risk Management — 风险管理

主要功能：

- 最大持仓限制。
- 单次交易金额限制。
- 最大亏损限制。
- 策略停止条件。
- 行情失效检测。
- 异常订单检测。
- 资金余额校验。
- 数据源连接状态监控。

风险管理模块应独立于策略模块。

风险校验优先于订单执行。

## 5. 非项目范围

以下功能暂不纳入开发路线：

- 真实资金交易。
- 真实钱包连接。
- 私钥及助记词管理。
- 充值与提现。
- 杠杆交易。
- 永续合约交易。
- 期货及期权交易。
- AI 老师。
- LLM API 集成。
- AI 自动投资决策。
- 多用户系统。
- 会员及付费订阅。
- 移动端原生 APP。
- 对外商业化数据服务。

如需扩展以上功能，必须重新进行需求及风险评估。

## 8. 数据管理原则

### 8.1 数据类型

系统数据分为以下类别：

| 类别 | 内容 |
|---|---|
| Reference Data | 交易所、交易对、市场配置 |
| Market Data | Ticker、K线、订单簿、成交记录 |
| Account Data | 虚拟账户、资产余额、持仓 |
| Trading Data | 订单、成交、手续费、资金流水 |
| Strategy Data | 策略定义、参数、运行记录 |
| Experiment Data | 实验配置、实验结果 |
| System Data | 系统配置、错误日志、运行状态 |

### 8.2 数据规范

- 所有数据必须明确来源。
- 市场时间及系统时间必须区分。
- 时间统一使用 UTC 存储。
- 金额及数量使用 Decimal 或等价的定点精度方案计算。
- 不得使用未经处理的浮点数进行核心资金计算。
- 缺失数据不得通过虚构数值补充。
- 实际行情与模拟数据必须明确区分。
- 原始行情与标准化行情应具有可追溯关系。
- 数据保留周期及存储上限应根据实验结果确定。

### 8.3 数据来源

初期候选数据来源：

- Binance。
- OKX。
- Bybit。
- Kraken。
- Coinbase。
- bitbank。

优先验证 BTC/USDT、ETH/USDT 现货交易对。

日本市场的 BTC/JPY、ETH/JPY 可作为补充研究对象。

最终接入范围取决于 API 可用性、地区限制、数据质量及使用许可。

## 9. 模拟账户设计原则

系统应支持多个相互独立的模拟账户。

账户用途包括：

- 手动交易。
- 长期持有实验。
- 套利实验。
- 量化策略实验。
- 历史回放实验。
- 基准策略对照实验。

默认初始资金暂定为 10,000 USDT，允许自定义。

不同交易所的资产余额必须独立管理。

资金不得在不同交易所之间无条件即时转移。

所有余额变化必须具备可追溯的资金流水。

系统应区分：

- 可用余额。
- 冻结余额。
- 持仓资产。
- 转移中的资产。

账户资产估值应注明使用的计价货币及价格来源。

## 10. 开发路线图

### Phase 0 — 技术可行性验证

目标：

验证真实市场数据的获取、标准化、质量检测及跨交易所价差分析能力。

交付物：

- API 验证脚本。
- 行情采集脚本。
- 统一行情数据模型。
- 数据质量检测工具。
- 价差分析工具。
- 实际采集数据。
- 技术验证报告。

不开发 Web 界面。

Phase 0 分为两个独立验收节点：

| 验收节点 | 内容 | 状态与阶段门槛 |
|---|---|---|
| Phase 0-A | API 可用、数据正确、短时采集正常、价差计算正确 | 通过后允许开始 Phase 1 |
| Phase 0-B | 长期稳定性、延迟统计、套利机会研究 | 必须实际完成实验后验收，不阻塞 Phase 1 |

Phase 0-A 的短时验证不得被描述为长期稳定性结论。Phase 0-B 通过前，相关研究结果保持 Pending。

### Phase 1 — 基础模拟交易

目标：

实现基于实时市场行情的虚拟资金现货交易系统。

主要功能：

- 虚拟账户。
- 订单簿驱动的模拟撮合与滑点。
- 限价单实时自动撮合。
- 模拟执行延迟。
- 交易引擎一致性验证。
- 持仓与盈亏。
- 数据持久化、后端服务、实时行情及 Web 应用。

Phase 1 按以下独立验收任务推进：

1. Task 1.1～1.4：账户、订单、基础成交、持仓与估值（Completed）。
2. Task 1.5：订单簿驱动的模拟撮合与滑点。
3. Task 1.6：限价单实时自动撮合。
4. Task 1.7：模拟执行延迟。
5. Task 1.8：交易引擎集成与一致性验证。
6. Task 1.9：数据持久化。
7. Task 1.10：后端服务与 REST API。
8. Task 1.11：实时行情服务。
9. Task 1.12：React 前端应用。
10. Task 1.13：前后端联调与 Phase 1 验收。

Task 1.5～1.8 保持 Python 领域层开发。以上任务按边界分别实现和验收；Phase 0-B 不阻塞 Phase 1，但重大数据质量问题必须触发行情依赖复审。

### Phase 2 — 跨交易所套利

目标：

研究跨交易所价格差异及实际可执行的套利空间。

主要功能：

- 多交易所接入。
- 实时价差监控。
- 净收益估算。
- 独立交易所虚拟账户。
- 套利模拟。
- 资金再平衡模拟。

### Phase 3 — 历史行情回放

目标：

通过历史行情进行可重复的模拟交易训练。

主要功能：

- 历史数据管理。
- 模拟时钟。
- 行情回放引擎。
- 回放速度控制。
- 历史模拟交易。
- 实验保存。

### Phase 4 — 量化策略与回测

目标：

建立可复现的策略实验环境。

主要功能：

- 策略接口。
- 策略参数管理。
- 自动模拟交易。
- 历史回测。
- 基准策略对比。
- 多策略收益分析。

### Phase 5 — 数据分析与风险管理

目标：

建立系统化的收益分析及策略风险评估能力。

主要功能：

- 资产曲线。
- 收益统计。
- 最大回撤。
- 风险敞口分析。
- 策略稳定性评估。
- 风险管理规则。
- 实验报告。

基础风险校验自 Phase 1 起实施，不延迟至 Phase 5。

## 11. 开发与协作规范

### 11.1 职责分工

| 角色 | 职责 |
|---|---|
| 项目负责人 | 需求确认、功能验收、研究方向 |
| ChatGPT | 需求分析、技术设计、金融知识讲解、方案审查 |
| Codex | 代码实现、接口验证、测试及重构 |
| Git Repository | 代码及文档的版本管理 |

协作原则：AI 负责开发和解释，程序负责采集和计算。长期采集任务由具备运行时长、容量限制和结构化报告能力的程序独立执行，不通过 AI 会话持续轮询完成。

### 11.2 开发流程

需求确认 → 技术方案 → 验收标准 → 代码实现 → 自动化测试 → 实际验证 → 文档更新 → Git 提交。

每个 Task 通过对应测试及验收后创建本地 Git Commit。Push 及 Merge 仍由项目负责人单独确认。

### 11.3 开发约束

- 不得擅自扩大当前阶段的开发范围。
- 不得擅自引入付费服务。
- 不得伪造接口验证结果。
- 不得使用 Mock 数据冒充真实行情。
- 不得未经确认修改核心金融计算规则。
- 不得接入真实交易权限。
- 重要架构变更必须记录。
- 核心资金计算逻辑必须具有单元测试。
- 未满足验收条件不得将任务标记为完成。

具体 AI 编码规范由 AGENTS.md 单独定义。

## 13. 项目成功标准

项目成功不以实际盈利作为衡量标准。

主要成功标准：

- 能够稳定获取真实市场数据。
- 能够准确识别并处理异常行情。
- 能够可信地模拟交易及资金变化。
- 能够客观评估交易策略。
- 能够复现历史实验结果。
- 能够理解交易成本及市场风险。
- 能够使用数据验证研究假设。
- 全程不需要投入真实交易资金。

即使研究结果表明某种交易策略无法盈利，该实验仍然具有研究价值。
