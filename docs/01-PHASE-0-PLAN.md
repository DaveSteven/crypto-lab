## 1. 项目背景

通过接入真实虚拟货币市场数据，建立一个使用虚拟资金进行交易、策略实验和市场研究的平台。

项目以金融知识学习、市场分析和交易策略验证为核心目标，不以短期投资盈利为首要目标。

## 2. Phase 0 目标

- 验证公开行情 API 的可用性。
- 验证日本地区网络访问情况。
- 验证实时行情采集与数据标准化的可行性。
- 验证跨交易所价格差异的计算方法。
- 建立后续模拟交易系统的数据基础。
- 学习市场行情及交易机制相关知识。

### 2.1 分阶段验收节点

| 验收节点 | 验收内容 | 对后续阶段的影响 |
|---|---|---|
| Phase 0-A | API 可用、数据正确、短时采集正常、价差计算正确 | 通过后可开始 Phase 1 基础开发 |
| Phase 0-B | 长期稳定性、延迟统计、套利机会研究 | 必须完成实际实验后单独验收，但不阻塞 Phase 1 |

任务归属：

- Phase 0-A：Task 0.1 至 Task 0.5。
- Phase 0-B：Task 0.6，以及 Task 0.7 中与长期实验和研究结论相关的内容。

Phase 0-A 的短时验证不得替代 Phase 0-B 的长期实验。Phase 0-B 尚未完成时，必须明确标记为 Pending。

## 3. 开发原则

- 零真实交易本金。
- 优先使用免费公开 API。
- 不使用交易账户 API Key。
- 不连接真实钱包。
- 不执行任何真实交易。
- 优先保证数据准确性，而非界面美观。
- 遵守交易所 API 访问频率及地区限制。
- 每项研究结论必须有实际数据支持。

## 5. 技术方案

### 5.1 技术选型

| 技术 | 用途 |
|---|---|
| Python 3.12 | 数据采集及分析 |
| CCXT | 统一交易所 REST API |
| CCXT Pro / 原生 WebSocket | 实时行情订阅 |
| asyncio | 异步并发 |
| Pydantic | 数据结构定义与校验 |
| pytest | 单元测试 |
| JSONL / CSV | 临时数据存储 |
| Git | 版本管理 |

Phase 0 暂不引入 React、FastAPI、PostgreSQL 和 Docker，避免不必要的开发复杂度。

### 5.2 数据采集流程

交易所公开 API → Exchange Adapter → 数据标准化 → 数据质量校验 → 本地存储 → 价差分析 → 研究报告。

### 5.3 统一数据结构

Ticker 至少包含以下字段：

- exchange：交易所标识
- symbol：标准化交易对
- market_type：市场类型
- bid：买一价
- ask：卖一价
- last：最新成交价
- bid_size：买一数量
- ask_size：卖一数量
- exchange_timestamp：交易所时间
- received_timestamp：本地接收时间
- latency_ms：可测量的延迟指标

时间统一采用 UTC，显示时可转换为 JST。

价格及数量计算使用 Decimal，避免浮点精度误差。

交易所未提供的字段应保留为空值，不得伪造。

## 7. 验收标准

| 验收节点 | 验证项 | 初步目标 |
|---|---|---|
| Phase 0-A | 可用交易所 | 至少2家具有相同现货交易对 |
| Phase 0-A | REST API | 正常获取公开行情 |
| Phase 0-A | WebSocket | 完成公开订阅、心跳及短时行情验证 |
| Phase 0-A | 数据结构 | 完成统一标准化 |
| Phase 0-A | 价差分析 | 正确计算可执行报价差异 |
| Phase 0-A | 异常处理 | 不使用失效行情进行计算 |
| Phase 0-B | 长期稳定性 | 完成规定时长的独立采集实验 |
| Phase 0-B | 延迟统计 | 生成可复现的结构化统计报告 |
| Phase 0-B | 套利研究 | 统计价差频率、持续时间及完整成本后的估算结果 |
| 全阶段 | 真实资金投入 | 0 |

不存在盈利机会不代表 Phase 0 失败。

Phase 0 的成功标准是能够可信地获取、处理和分析市场数据，而不是证明套利一定能够盈利。

Phase 0-A 通过不代表 Phase 0-B 通过，也不得据此声称系统已完成长期稳定性验收。
