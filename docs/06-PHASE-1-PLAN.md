## 1. 目标

基于已经验证的真实市场数据，构建只使用虚拟资金的现货模拟交易基础能力。

Phase 1 不连接真实账户、不使用交易权限 API、不连接钱包，也不执行真实订单。

## 2. 开发顺序

- [x] 建立交易所隔离的模拟账户。

- [x] 所有余额变化生成不可变资金流水。
- [x] 禁止可用余额及冻结余额变为负数。
- [x] 支持初始虚拟资金、冻结和释放操作。
- [x] 覆盖重复流水、非法资产及边界值测试。

### Task 1.2 — 模拟订单模型

- [x] 定义现货市价单及限价单。
- [x] 定义订单状态转换。
- [x] 下单前执行余额校验及资金冻结。
- [x] 支持取消订单及释放资金。

### Task 1.3 — 模拟成交引擎

- [x] 买入参考 Ask，卖出参考 Bid。
- [x] 引入手续费和明确的成交模型。
- [x] 支持部分成交及失败结果。
- [x] 生成成交记录和结算流水。

当前成交模型约束：

- 只接受质量状态为 VALID 且交易品种一致的 Ticker。
- 市场买入使用 Ask，市场卖出使用 Bid，不使用 Last Price。
- 手续费当前以计价资产收取，并由调用方显式传入费率。
- 限价买入不得高于限价成交，限价卖出不得低于限价成交。
- 多资产结算使用批量原子流水，任一余额不足时整次成交失败。
- 当前成交价格及部分成交数量由调用方提供；订单簿驱动的自动撮合属于后续增强。

### Task 1.4 — 持仓与估值

- [x] 计算持仓数量及成本。
- [x] 区分已实现及未实现盈亏。
- [x] 明确估值价格来源和时间。

当前持仓模型约束：

- 使用移动平均成本法，买入手续费计入持仓成本。
- 卖出实现盈亏等于卖出金额减手续费和对应持仓成本。
- 未实现盈亏使用同一交易品种有效 Ticker 的 Bid 估值，不使用 Last Price。
- 估值结果记录价格事件 ID、接收时间和价格依据。
- 持仓可由成交历史重建；重复、乱序及超额卖出成交被拒绝。

## 3. Task 1.1 验收标准

- 初始资金只存在于指定模拟账户和交易所。
- 相同资产区分 available 与 locked。
- 冻结金额从 available 转入 locked，总额不凭空变化。
- 释放金额从 locked 返回 available，总额不凭空变化。
- 任何会产生负余额的操作必须整体失败，不得部分写入。
- 重复 entry ID 不得重复影响余额。
- 余额可由资金流水完整重建。

## 4. 开发原则

- Account Ledger 是模拟余额的权威来源。
- 账户之间及交易所之间不得隐式转移资金。
- 不使用 float 处理金额和数量。
- Task 1.5 按子任务顺序引入 Web 框架、数据库及前端工具，不一次性搭建全部基础设施。
- 每个 Task 1.5.x 应控制在单一技术边界内，避免无关重构和跨任务实现。
- PostgreSQL、WebSocket 和前端运行产生的长期进程不得阻塞 AI 开发会话。
- Phase 0-B 的长期实验结果不会阻塞本计划，但发现重大数据问题时必须重新评估行情依赖。
